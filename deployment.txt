CONDUIT LOCAL TEST AND PUBLISHING GUIDE
=======================================

SYSTEM SHAPE
------------

Conduit has two runtime deliverables:

1. Browser extension
   - Runs inside Chrome, Edge, or another Chromium browser.
   - Connects to the local daemon over an authenticated WebSocket.
   - Performs tab, navigation, snapshot, interaction, and screenshot actions.

2. Host backend
   - The Conduit daemon runs on the user's computer and binds to 127.0.0.1 by default.
   - The CLI and MCP server talk to the daemon.
   - The daemon authenticates the extension and enforces permissions, domain policy,
     confirmations, payload limits, upload allowlists, sessions, and audit logging.

The GitHub Pages documentation site is a third deployment, but it is not part of
the browser-control runtime.


TEST FROM SOURCE ON WINDOWS POWERSHELL
--------------------------------------

Requirements: Git, Node.js 22+ (Node 24 LTS recommended), pnpm 9.15.9, and Chrome
or Edge.

From D:\conduit:

  corepack enable
  corepack pnpm@9.15.9 install --frozen-lockfile
  pnpm build
  node packages/cli/bin/conduit.js start
  node packages/cli/bin/conduit.js status
  node packages/cli/bin/conduit.js doctor

Find the built extension and reveal the local token:

  node packages/cli/bin/conduit.js extension path
  node packages/cli/bin/conduit.js extension token

Treat the token as a password. Do not paste it into a website, issue, screenshot,
chat, or source file.

Load the extension:

1. Open chrome://extensions or edge://extensions.
2. Enable Developer mode.
3. Click Load unpacked.
4. Select D:\conduit\apps\extension\dist (or the path printed by the CLI).
5. Open the Conduit extension popup.
6. Enter port 9222 and the token printed by "extension token".
7. Save. The popup should report a connected state.

Confirm the full connection:

  node packages/cli/bin/conduit.js status
  node packages/cli/bin/conduit.js doctor

The status should report extensionConnected: true. A disconnected warning before
the popup is configured is expected.


RUN A SAFE MANUAL BROWSER TEST
------------------------------

Grant only the permissions needed for this test and allow example.com:

  node packages/cli/bin/conduit.js config set security.permissions '["browser.read","browser.navigate","browser.interact","browser.forms"]'
  node packages/cli/bin/conduit.js allow-domain example.com
  node packages/cli/bin/conduit.js restart

Then reconnect/reopen the extension popup if needed and run:

  node packages/cli/bin/conduit.js browser open https://example.com
  node packages/cli/bin/conduit.js browser tabs
  node packages/cli/bin/conduit.js browser snapshot --mode interactive
  node packages/cli/bin/conduit.js browser text
  node packages/cli/bin/conduit.js browser screenshot

For a click/type test, use a page you control, take a fresh interactive snapshot,
then use the returned temporary element IDs:

  node packages/cli/bin/conduit.js browser click --element e1
  node packages/cli/bin/conduit.js browser type --element e2 --text "hello"

Element IDs expire after navigation or significant rerendering. Take a new snapshot
when an element reference becomes stale.

Stop the daemon when finished:

  node packages/cli/bin/conduit.js stop


AUTOMATED VALIDATION
--------------------

  pnpm format:check
  pnpm lint
  pnpm typecheck
  pnpm test
  pnpm test:coverage
  pnpm build
  pnpm docs:build
  pnpm test:e2e

The E2E test starts the daemon, launches Chromium with the unpacked extension,
authenticates it, exercises the vertical slice, and cleans up.


CONNECT AN MCP CLIENT
---------------------

Start and connect the daemon/extension first. Configure the MCP client to launch:

  command: node
  args:
    - D:\conduit\packages\cli\bin\conduit.js
    - mcp

Use an absolute path. Call conduit_status before browser tools. The MCP process is
an adapter to the same local daemon; it does not replace the daemon or extension.


HOW PUBLISHING SHOULD WORK
--------------------------

A. Extension release

- Build a clean extension with "pnpm extension:package".
- Validate apps/extension/dist and the requested permissions.
- Create icons, store screenshots, privacy disclosures, and support information.
- Zip the contents of apps/extension/dist (manifest.json must be at the ZIP root).
- Upload the ZIP separately to the Chrome Web Store and Microsoft Edge Add-ons.
- Store signing/store credentials only in protected release secrets, never Git.
- Release updates only after the browser E2E and security workflows pass.

B. Backend/CLI release

- Package the CLI, daemon, MCP adapter, and required internal packages as a tested
  npm release or as signed platform installers/GitHub Release archives.
- Add package files/exports/repository/license metadata and test installation from
  the produced tarballs in an empty directory.
- Add provenance, checksums, release notes, and a versioned release workflow.
- Users install the backend on the same machine as the browser, then install the
  extension from the browser store and pair it using the local token.

C. Documentation release

- GitHub Actions builds apps/docs and deploys it to GitHub Pages.
- Expected URL: https://err0rgod.github.io/conduit/

CURRENT RELEASE STATUS
----------------------

- Source installation and unpacked-extension use are supported and tested.
- GitHub Actions produces an extension artifact for every relevant main build.
- No npm package or Chrome/Edge store listing has been published yet.
- Do not announce one-command npm or browser-store installation until release
  packaging and clean-install tests have been added and exercised.
- Remote access remains disabled by default. Do not expose port 9222 publicly.
  Non-loopback operation requires explicit remote mode and TLS; use a trusted
  private network such as Tailscale or WireGuard.
